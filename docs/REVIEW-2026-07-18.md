# SiteForge — Full Internal Review, 2026-07-18

This is the review that reset the project's direction. It was produced by a multi-agent
orchestration: eight review dimensions run in parallel (112 raw findings) plus a pre-seeded
orchestrator checklist (12), deduplicated into **81 unique findings**. Findings were then routed
through a two-verifier adversarial check (coverage note below), and a four-perspective product panel
(small-business owner, operator, admin architect, competitive analysis) produced 56 proposals.

> **Verification coverage — stated honestly.** Adversarial verification completed the first 32
> findings, highest severity first, before the session hit its budget ceiling. The remaining 49,
> mostly medium and low, are rated by engineering judgement rather than by two-verifier consensus.
> Sections 2 and 3 below itemise 71 of the 81: the 14 critical/high findings and the 57 medium/low
> ones. The other 10 are not reproduced individually. Every entry that is listed is marked either
> fixed or outstanding. Test coverage of the fixes is real but partial: `test/unit.mjs` covers the
> brand-name, address, opening-hours, font-sanitisation and contrast fixes, and
> `scripts/smoke-admin.sh` covers the admin surface end to end. There is no assertion per finding.

> **A note for readers of the public repository.** The batch numbers quoted here, notably the 97.6%
> mean clone score over the 60-site corpus, come from local runs. The run logs, screenshots and score
> reports are **not committed**: `runs/`, `proof/` and `corpus/*.png` are gitignored, and the corpus
> manifest itself is withheld because the 60 sites belong to third-party businesses that never
> volunteered as benchmark subjects. `corpus/COMPOSITION.md` gives the platform and vertical
> breakdown instead. What is in the repository is the scorer (`src/score.ts`) and the batch driver
> (`src/clone-loop.ts`), so the run is reproducible in principle but is not attested by anything you
> can check here. Treat the figures as development-time observations.

## 1. Overall conclusions

**Code quality.** Both tracks, `forge` (render, extract, regenerate) and `clone` (pixel-level
reproduction), are in decent engineering shape. On the clone side, asset localisation, band-aligned
scoring and subprocess isolation are all solid pieces of work.

But there are **two critical security holes, several high-severity usability defects**, and, more
importantly, a **strategic split at the design level**: the README describes only `forge`, while all
recent iteration and the entire 60-site scoring effort went into `clone`. Neither product closes the
loop to the point where you could charge a customer for it.

**The truth about the scoring system.** The 97.6% mean score from the clone batch measures one thing:
*how self-consistent a reproduction of a frozen desktop frame is.* It is **completely blind to lost
interactivity, broken forms, dead links, mobile layout and SEO regressions.** That headline number
badly overstates usability. This is the most important conclusion of the review, and it is a
conclusion about the product, not about the code.

**What this round did about it.** The forge track was brought up to a loop that can actually be
delivered to a customer: the fix list below, plus a new admin console for creating a site from a
URL, editing its content and theme, previewing it and collecting leads.

## 2. Critical / High findings and how they were resolved

| # | Severity | File | Problem | Resolution |
|---|---|---|---|---|
| 1 | **critical** | render / capture | **SSRF.** Arbitrary URLs went to a headless browser and to asset fetching with no filtering of private ranges or cloud metadata endpoints (`169.254.169.254`). | Fixed. `safe.ts:urlAllowed` is the single choke point; wired into the forge CLI and into both the "create site" and "re-capture" entry points of the admin console. |
| 2 | **critical** | `capture.ts` | **Path traversal into `rm -rf`.** The batch `tag` was never sanitised and was used to build `outDir`, which is then removed recursively, so a crafted tag deletes an arbitrary directory. | Fixed. `safe.ts:assertTag` whitelist, enforced at the `clone-loop` and `crawl` entry points. |
| 3 | high | `styles.ts` | **Font family names were interpolated into `<style>` unsanitised**, a stored XSS / CSS-injection path running from the scraped site all the way into the delivered site. (**Adversarially CONFIRMED.**) | Fixed. Two independent whitelist filters: `styles.ts:safeFont` and `brand.ts:cleanFont`. |
| 4 | high | `content.ts` | `brandFromTitle` split on bare hyphens and then took the *shortest* segment, so brand names were systematically wrong: `K-OAK` became `OAK`, and SEO-style titles yielded the city name instead of the business. (**CONFIRMED.**) | Fixed. Rewritten: split only on space-delimited separators, cross-check against the domain stem, prefer document order. The shortest-segment heuristic is gone. |
| 5 | high | `seo.ts` | `og:image` and the JSON-LD `image` used relative paths, so social cards and rich results silently failed; `canonical` and `og:url` were missing entirely. | Fixed. Introduced a per-site `baseUrl`; emits absolute `og:image` / `og:url` / `canonical` plus Twitter card tags. |
| 6 | high | `styles.ts` | The brand font was extracted but the generated site never loaded a webfont, so any non-system font fell back silently to `system-ui`. | Fixed. `seo.ts` detects non-system fonts and injects the corresponding Google Fonts `css2` link with `display=swap`. |
| 7 | high | `render.ts` | A self-identifying user agent got the crawler served a Cloudflare/WAF challenge page, and the extractor happily consumed the garbage. | Fixed. Extracted `browser.ts` with a shared, realistic Chrome UA; both tracks now use it. |
| 8 | high | `clone-loop.ts` | On timeout the `SIGKILL` only reached the Node worker. The Chromium process tree was orphaned, and on the 1.9 GB deployment box the orphans snowballed into OOM. | Fixed. `spawn(detached: true)` creates a process group; the timeout path calls `kill(-pid)` to take down the whole group. |
| 9 | high | `clone-loop.ts` | Default concurrency was 4. Four simultaneous Node + Chromium pairs on a 1.9 GB box is a guaranteed OOM. | Fixed. Default is now `SF_CONCURRENCY=1`, and `envNum` rejects invalid values instead of silently producing `0` or `NaN`. |
| 10 | high | `capture.ts` | Both navigation attempts failing was swallowed silently, so an `about:blank` blank page scored roughly 100% and was recorded as a success. | Fixed. A double navigation failure now throws instead of masquerading as a successful capture. |
| 11 | high | `content.ts` | The service-card `description` had a comment claiming it filled in "the nearest description", but it always wrote an empty string. Dead code. | Fixed. `render.ts` now extracts sections (heading, then the immediately following paragraph); service cards and the about block are filled from them. |
| 12 | high | `index.ts` | The CLI `slug` was unsanitised: path traversal to write files anywhere. | Fixed. `safe.ts:assertSlug` whitelist. |
| 13 | high | `capture.ts` | The `@import` fallback path still used `ctx.request.get`, even though a comment in the same file already recorded that this API crashes the process on a malformed certificate. | Fixed. Routed through `fetchBuf` (Node `fetch`). |
| 14 | high | `seo.ts` | No `canonical` / `og:url`. Since the content is copied from an old site that is usually still online, the new site is duplicate content by construction, with no canonical signal to resolve it. | Fixed alongside #5: once `baseUrl` is set, the build emits `canonical`, `sitemap.xml` and `robots.txt`. |

Two pieces of deeper clone-track hardening were **deliberately deferred to roadmap P1**: rendering
untrusted sites under `--no-sandbox` (in the shared launcher, `browser.ts`), and the SSRF fan-out
during asset localisation. Network isolation of the rendering machine is the more fundamental
mitigation, and it is not something a single code change can close.

## 3. Medium / Low findings, grouped (57 items)

### Extraction quality (most fixed)

- Fixed. Contact extraction only understood Canadian postal codes. Added US "state + ZIP" anchoring,
  and the address window now strips phone and email fragments *before* looking for the street number.
  That fragment leak is what produced the `"0188 Email:"` contamination.
- Fixed. Opening hours only ever captured a single line. Now collected globally and merged across
  lines (handles `9am` and `9:00`, `Mon-Fri`, `Closed`).
- Fixed. Colour extraction only recognised `rgb`/`rgba` and ignored alpha entirely, so a
  semi-transparent dark overlay was counted as a solid colour. Weights are now discounted by alpha.
- Fixed. Derived colours had no WCAG check. Body text is now forced to contrast ≥ 4.5, secondary
  text ≥ 3, and on dark sites the decision uses the real `body` background rather than being misled
  by the sheer area of a large hero.
- Fixed. Low-saturation and black/white/grey brands were being forced to a default blue, and dark
  sites were flipped to white. The primary-colour candidate chain now has a mid-lightness fallback,
  and dark sites keep a dark theme.
- Fixed. Text from hidden menus and modals was being mixed into the content. The renderer now
  filters elements that are `display:none`, `visibility:hidden`, or effectively zero-opacity.
- Fixed. The hero image selector was picking the large logo in the header. Hero now excludes images
  inside `header`/`nav`; logo detection prefers logo-shaped images *inside* the header.
- Outstanding (roadmap): inline SVG logos are invisible to the extractor; multi-location businesses
  get their NAP details mixed together; `oklch`/`lab` colour spaces are unsupported.

### SEO and accessibility (most fixed)

- Fixed. `<html lang>` was hardcoded to `en`; it now inherits the source site's language.
- Fixed. Mobile navigation was `display:none` with no fallback at all. Added a pure-CSS `<details>`
  hamburger menu, with no JavaScript.
- Fixed. JSON-LD was missing `url`, and semantic landmarks were absent. Added the JSON-LD `url`, a
  `<main>` element, and `aria-hidden` on the decorative footer icons.
- Outstanding: the favicon uses the raw logo image with no 32px/180px variants generated;
  `openingHoursSpecification` is not emitted as structured data; images lack width/height, so the
  page suffers avoidable CLS.

### Clone-track robustness (partly fixed, partly deferred)

- Fixed. Pages that fail to fetch during a crawl are now removed from the URL-to-file map, so
  cross-page link rewriting can no longer point at a file that was never written.
- Fixed. A crawled sub-page whose slug came out as `assets` used to overwrite the home page's asset
  directory. It is renamed to `page-assets`.
- Fixed. Worker error messages were truncated at 300 characters, which cut off the actionable part,
  for example the `playwright install` hint. Raised to 2000.
- Fixed. Batch reports now carry a `generatedAt` timestamp, and `clone-loop` pre-allocates slugs for
  the whole batch so that two URLs on the same hostname cannot collide.
- Partly fixed. The `@import` rewrite was flagged for doing string-level substitution. The fetch
  behind it moved to `fetchBuf` (#13) and the `url(...)` rewrite now uses `split`/`join` so every
  occurrence is replaced, but the `@import` branch itself still calls `String.replace` with the
  inlined stylesheet as the replacement string, where `$&` and friends are still interpreted. Worked
  around rather than closed.
- Outstanding (deeper clone-track work, on the roadmap): the score is blind on
  background-image-dominated pages; `<base>` is not resolved; conditional `@media` / `@layer` styles
  are not handled; single-page clones do not rewrite `<a>` or `<form>` targets; `runs/` has no
  cleanup policy; there is no resume after a crash; `iframe` and `video` content is not localised;
  redistribution licensing for cloned fonts and stock images is unaddressed; mobile is not scored at
  all.

### Engineering and documentation (fixed)

- Fixed. The README had drifted badly. It documented a `template/` directory and an `npm run
  preview` script that no longer existed, and said nothing whatsoever about the clone track.
  Rewritten to reflect the actual two-track reality.
- Mostly fixed. Five `SF_*` environment variables were undocumented: `SF_CONCURRENCY`, `SF_TIMEOUT`,
  `SF_LIMIT`, `SF_FREEZE` and `SF_DEBUG`. The batch and admin variables are now documented in the
  README and `docs/ADMIN.md`. `SF_DEBUG`, an internal capture-debug flag, still is not.
- Fixed. Output was split between `sites/` and `runs/` with no unified way to look at it. The admin
  console now reads and writes both, with preview.
- Fixed. There were zero tests. Added `test/unit.mjs` (12 assertions) and `scripts/smoke-admin.sh`,
  an end-to-end pass over the admin API (20 assertions at this point in the round, 26 after the
  security re-review in §6).
- Outstanding: a minimal CI. The code is under version control, but nothing runs `test/unit.mjs` or
  the smoke script automatically, so there is no gate between a bad commit and the next batch run.
  CI is the first item on the roadmap.

## 5. Methodology

- **Eight dimensions:** forge correctness, clone correctness, security, robustness, SEO and
  accessibility, extraction quality, architecture, and developer experience / documentation.
- **Adversarial verification:** each finding that reached this stage got one "sceptic", whose
  default verdict is *false* unless the finding can be reproduced from the code, plus one independent
  reviewer who rebuilds the reasoning from the source. A finding is CONFIRMED only with both votes.
- The first 32 findings, highest severity first, completed two-person verification; the high items
  including #3 and #4 came back CONFIRMED with high confidence. The synthesis stage never ran because
  of the budget ceiling, so this document is a manual synthesis.

## 6. Adversarial re-review of the new code

After the fixes landed, a separate adversarial reviewer was pointed at the *new* code, meaning the
admin server plus the fixes themselves, with instructions to back every claim with runtime evidence.

### Newly introduced, and fixed

- **HIGH (fixed): the static preview route bypassed authentication and leaked lead PII, the audit
  log and internal JSON.** `/sites/**` never went through `authed()`, so an unauthenticated
  `GET /sites/<slug>/leads.jsonl` returned customer names, phone numbers and email addresses, and the
  same applied to `.audit.jsonl` and `content.json`.
  **Fix:** `serveStatic` now serves only a whitelist of publishable web files. Anything ending in
  `.json`/`.jsonl`, and any path segment starting with a dot, returns 404. The smoke test asserts
  both halves: the sidecar files 404, and a genuinely published `index.html` still returns 200.
- **MEDIUM (fixed):** the server bound to `0.0.0.0` by default with no token, so the default is now
  `127.0.0.1`. `SF_ADMIN_PORT` and `SF_JOB_TIMEOUT` were parsed with `Number()` and died on `NaN`,
  so they moved to `envNum`. The public lead endpoint had no abuse guard, so it now refuses new
  submissions with a 429 once a site's `leads.jsonl` passes 5 MB, and per-IP rate limiting is
  explicitly left to a reverse proxy. Node-side re-fetching during clone asset localisation had no
  SSRF check, and now goes through `urlAllowed`.
- **LOW (fixed):** `?token=` in the query string leaks into access logs, so only the `Bearer` header
  is accepted now. Uploads were not byte-validated, so magic-number checks were added. The regex for
  content image references allowed `assets/..`, and was tightened to image extensions only. The
  frontend `esc` helper did not escape single quotes. The in-memory jobs table had no upper bound,
  and is now capped at 100 with finished jobs evicted first.

### A reviewer false positive, overturned by runtime evidence

- **Claim: "`urlAllowed` can be bypassed with integer, hexadecimal or octal IP encodings."**
  Rejected. The reviewer had tested the **bare regular expression** in isolation. In the real code
  path, `urlAllowed` first passes the input through `new URL().hostname`, which normalises
  `2130706433`, `0x7f000001`, `0177.0.0.1`, `127.1` and `0xA9FEA9FE` to canonical dotted-quad form
  *before* the checks run. All ten encodings tested were blocked.

### Held up under adversarial construction (judged OK)

`serveStatic` path traversal (blocked under every encoding tested), font CSS injection (double
sanitised by `safeFont` and `cleanFont`), JSON-LD and React escaping, `ensureContrast` (no infinite
loop, no `NaN`), `leads.jsonl` injection, ReDoS in `RE_HOURS` and `RE_ZIP_US`, and process-group
timeout kills.

### What this does *not* cover

`urlAllowed` is a **literal-value defence**, and its own comment says so: DNS rebinding still
requires network isolation upstream, on a rendering machine with its own network segment. That is
why the deeper hardening stayed on the roadmap rather than being marked fixed here. `urlAllowed` is
also bypassed on purpose when `SF_ALLOW_PRIVATE=1` is set, which is how the local-fixture tests
reach `127.0.0.1`; that variable must never be set in production.

After the re-review, `test/unit.mjs` (12 assertions) and `scripts/smoke-admin.sh` (26 assertions as
reviewed; the script has grown since) both pass. The smoke coverage added in this round is
sidecar-file protection, upload magic numbers and path traversal. It deliberately does *not* cover
SSRF: the script runs its local fixture with `SF_ALLOW_PRIVATE=1`, which switches `urlAllowed` off,
so the blocking behaviour is checked by calling `urlAllowed` directly instead.
